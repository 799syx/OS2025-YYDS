# YYDS-OS 设计文档

## 1. 项目概述

### 1.1 项目背景

YYDS-OS 是基于 MIT xv6-riscv 教学操作系统开发的增强型小型内核。项目目标是在保持 xv6 简洁性的同时，融合现代操作系统的先进特性，包括 Android、Linux 和 HarmonyOS 的优秀设计理念。

### 1.2 设计目标

- 保持内核的简洁性和可读性
- 实现丰富的系统调用接口（144个）
- 融合多系统优秀特性
- 提供完善的测试用例

### 2.1 整体架构

```
┌─────────────────────────────────────────────────────────────────┐
│                        用户空间 (User Space)                     │

├─────────────────────────────────────────────────────────────────┤
│                              ecall (陷入内核)                    │
├─────────────────────────────────────────────────────────────────┤
│                        内核空间 (Kernel Space)                   │
├─────────────────────────────────────────────────────────────────┤
│  ┌─────────┬─────────┬─────────┬─────────┬─────────┬─────────┐ │
│  │ 进程管理 │ 内存管理 │ 文件系统 │ 网络协议 │   IPC   │ 调度器  │ │
│  │ proc/   │   mm/   │   fs/   │ network/│ Binder  │QoS/MLFQ │ │
│  └─────────┴─────────┴─────────┴─────────┴─────────┴─────────┘ │
├─────────────────────────────────────────────────────────────────┤
│                      中断/陷阱处理 (trap.c)                      │
├─────────────────────────────────────────────────────────────────┤
│              硬件抽象层: UART | PLIC | CLINT | VirtIO | E1000    │
├─────────────────────────────────────────────────────────────────┤
│                      RISC-V 64位 硬件平台                        │
└─────────────────────────────────────────────────────────────────┘
```

### 2.2 目录结构

```
kernel/
├── asm/          # 汇编代码（entry.S, swtch.S, trampoline.S）
├── driver/       # 设备驱动（console, uart, virtio_disk）
├── filesystem/   # 文件系统核心（fs.c, file.c, bio.c, log.c）
├── fs/           # 扩展文件系统（sysfs, hmdfs）
├── include/      # 内核头文件
├── interrupt/    # 中断处理（trap.c, plic.c）
├── lib/          # 库函数（printf.c, string.c）

├── network/      # 网络协议栈（net.c, e1000.c, pci.c）
├── proc/         # 进程管理（proc, pipe, exec, embassy, qos, binder, cgroups, ability）
└── sys*.c        # 系统调用实现
```

## 3. 核心模块设计

### 3.1 进程调度模块

#### 3.1.1 MLFQ 多级反馈队列调度器

**设计思路：**
- 实现多级优先级队列，高优先级进程优先执行
- 动态调整进程优先级，防止饥饿
- 支持时间片轮转

**核心数据结构：**
```c
struct proc {
    int priority;           // 当前优先级
    int original_priority;  // 原始优先级
    int time_slice;         // 剩余时间片
    // ...
};
```

#### 3.1.2 Embassy 异步调度器

**设计思路：**
- 借鉴 Rust Embassy 框架的异步任务模型
- 4级优先级：CRITICAL、HIGH、NORMAL、LOW
- 支持延时等待、事件触发、优先级提升

**核心接口：**
```c
int embassy_spawn(void (*fn)(void*), void *arg, int priority);
void embassy_yield(void);
void embassy_delay_ms(int ms);
int embassy_event_wait(int event_id);
```

#### 3.1.3 QoS 服务质量调度（HarmonyOS 特性）

**设计思路：**
- 6级服务质量等级，对应不同的调度策略
- 支持截止时间感知、I/O 优先级提升
- 动态负载均衡

**QoS 等级：**
| 等级 | 名称 | 时间片 | 用途 |
|------|------|--------|------|
| 0 | USER_INTERACTIVE | 5ms | 用户交互 |
| 1 | DEADLINE_REQUEST | 8ms | 截止时间敏感 |
| 2 | USER_INITIATED | 10ms | 用户发起 |
| 3 | DEFAULT | 15ms | 默认 |
| 4 | UTILITY | 20ms | 工具类 |
| 5 | BACKGROUND | 30ms | 后台任务 |

### 3.2 内存管理模块

#### 3.2.1 Slab 分配器

**设计思路：**
- 针对小对象分配优化，减少内存碎片
- 预分配多种大小的对象缓存
- 支持统计信息查询

**缓存大小类：**
```c
static int slab_sizes[] = {32, 64, 128, 256, 512};
```

#### 3.2.2 VMA 虚拟内存区域管理

**设计思路：**
- 增强的虚拟内存区域管理
- 支持匿名映射、文件映射、共享映射
- 缺页异常处理优化

**VMA 结构：**
```c
struct vma_entry {
    uint64 start;      // 起始地址
    uint64 end;        // 结束地址
    int flags;         // VMA_READ | VMA_WRITE | VMA_EXEC | ...
    struct file *file; // 关联文件（文件映射）
    int offset;        // 文件偏移
};
```

#### 3.2.3 cgroups 资源控制（Linux 特性）

**设计思路：**
- 实现进程组资源限制
- 支持 CPU、内存、I/O、PID 四种控制器
- 层次化的 cgroup 管理

**控制器功能：**
| 控制器 | 功能 |
|--------|------|
| CPU | cpu_shares, cpu_quota |
| Memory | memory_limit, memory_usage |
| I/O | io_bps_limit, io_iops_limit |
| PIDs | pids_max, pids_current |

### 3.3 进程间通信模块

#### 3.3.1 Binder IPC（Android 特性）

**设计思路：**
- 高效的跨进程通信机制
- 服务注册与发现

**核心接口：**
```c
int binder_register(char *name, int handle);  // 注册服务

int binder_call(int handle, void *data, int size);  // 调用服务
```

#### 3.3.2 共享内存

**设计思路：**
- 支持多进程共享同一物理内存区域
- 引用计数管理
- 支持读写权限控制

#### 3.3.3 消息队列

**设计思路：**
- FIFO 消息传递
- 支持阻塞/非阻塞模式
- 消息优先级

### 3.4 文件系统模块

**设计思路：**

#### 3.5.1 Ability 框架（HarmonyOS 特性）

**设计思路：**
- 应用能力抽象

**Ability 类型：**

### 3.6 高级调度模块

#### 3.6.1 实时调度 (Real-Time Scheduling)

**设计思路：**
- 支持 POSIX 实时调度策略
- 实时进程优先于普通进程调度
- 优先级范围 0-99

**调度策略：**
| 策略 | 说明 |
|------|------|
| SCHED_NORMAL (0) | 普通 MLFQ 调度 |
| SCHED_FIFO (1) | 实时先进先出，不抢占同优先级 |
| SCHED_RR (2) | 实时轮转，同优先级时间片轮转 |
| SCHED_DEADLINE (3) | EDF 截止时间调度 |

#### 3.6.2 Deadline 调度 (EDF 算法)

**设计思路：**
- 最早截止时间优先 (Earliest Deadline First)
- 支持周期性任务
- 运行时间预算管理

**核心参数：**
```c
struct proc {
    uint64 deadline;           // 截止时间
    uint64 period;             // 周期
    uint64 runtime;            // 运行时间预算
    uint64 runtime_remaining;  // 剩余运行时间
};
```

#### 3.6.3 CPU 亲和性 (CPU Affinity)

**设计思路：**
- SMP 多核调度优化
- 进程绑定到特定 CPU 核心
- 自动负载均衡

**负载均衡策略：**
| 策略 | 说明 |
|------|------|
| LB_NONE (0) | 不进行负载均衡 |
| LB_PERIODIC (1) | 周期性负载均衡 |
| LB_ON_IDLE (2) | 空闲时负载均衡 |
| LB_AGGRESSIVE (3) | 激进负载均衡 |

**核心接口：**
```c
int sched_setaffinity(int pid, uint32 mask);  // 设置 CPU 掩码
int sched_getaffinity(int pid, uint32 *mask); // 获取 CPU 掩码
void load_balance(void);                       // 执行负载均衡
```

### 3.7 安全模块

**权能类型：**
| 权能 | 说明 |
|------|------|

| CAP_KILL (4) | 发送信号给任意进程 |

| CAP_NET_BIND (7) | 绑定特权端口 |

### 3.8 进程管理增强

#### 3.8.1 进程冻结 (Freezer)

**设计思路：**
- 类似 Android 的后台进程管理
- 支持低内存时自动冻结
- cgroup 级别的冻结控制

**冻结优先级：**
| 优先级 | 说明 |
|--------|------|
| CRITICAL (0) | 关键进程，不冻结 |
| FOREGROUND (1) | 前台进程 |
| VISIBLE (2) | 可见进程 |
| SERVICE (3) | 服务进程 |
| BACKGROUND (4) | 后台进程 |
| CACHED (5) | 缓存进程 |

**核心接口：**
```c

int freeze_cgroup(int cgroup_id);         // 冻结 cgroup

```

#### 3.8.2 进程快照 (Checkpoint/Restore)

**设计思路：**

- 内核上下文 (context)

**核心接口：**

## 4. 创新点与亮点

### 4.1 多系统特性融合

YYDS-OS 创新性地融合了三大主流操作系统的优秀特性：

| 来源 | 特性 | 创新点 |
|------|------|--------|
| Android | Binder IPC | 轻量级实现，适配教学内核 |
| Android | 进程冻结 (Freezer) | 后台进程管理，低内存优化 |
| Linux | cgroups | 简化版资源控制，IO/网络带宽限制 |
| Linux | 权能系统 (Capability) | 30种权能位，细粒度权限控制 |
| Linux | CPU亲和性 | SMP调度优化，负载均衡 |
| Linux | Futex | 快速用户态互斥锁 |
| Linux | 实时调度 | FIFO/RR/Deadline (EDF) |
| HarmonyOS | Ability框架 | 应用能力抽象，IPC通信，生命周期管理 |
| HarmonyOS | HMDFS | 分布式文件系统，跨设备同步 |
| HarmonyOS | QoS调度 | 服务质量感知调度 |

### 4.2 Embassy 异步调度器

借鉴 Rust Embassy 框架设计，实现了内核级异步任务调度：
- 协作式多任务
- 优先级提升防饥饿
- 事件驱动模型

**执行器设计：**
- **Thread Poll**：循环从执行器取出最高优先级任务调度执行，任务 poll 完后设置为非就绪，继续查找下一个最高优先级任务
- **Interrupt Poll**：中断抢占式调度，对无栈任务进行模拟压栈，使用 PendSV 软中断实现统一任务切换

**栈复用机制：**
- 主动让权时：所有任务共用一个栈区，无私有栈
- 被抢占时：分配私有栈保存上下文
- 恢复执行时：合理回收不使用的栈

### 4.3 Slab 分配器优化

针对内核小对象分配场景优化：
- 减少内存碎片
- 提高分配效率
- 支持统计监控

### 4.4 系统调用丰富度

从 xv6 原有的 21 个系统调用扩展到 144 个，涵盖：
- 进程管理与调度
- 内存管理
- 文件系统
- 网络通信
- 进程间通信
- 用户管理

## 5. 技术难点与解决方案

### 5.1 模拟压栈与内存对齐

**问题**：传入的栈指针可能不是8字节对齐

**解决方案**：
- 栈指针先向上加4字节再截取8字节对齐
- 满堆栈压栈时先下移栈指针再压入
- 最终栈指针偏移17个4字节（保存17个寄存器）

### 5.2 临界区与任务边界

**问题**：如何确定代码属于哪个任务执行

**解决方案**：
- 只在竞争资源（全局变量）访问处设置临界区
- 操作系统启动后任何时刻代码都对应一个任务
- 执行器的 poll 和 interrupt poll 都属于当前任务代码

### 5.3 统一异步任务与同步任务

**问题**：同步任务和异步任务的 TCB 结构不同

**解决方案**：
- 同步任务套上 async 闭包转换为无 await 点的 future
- 统一栈分配模式：抢占时分配私有栈，让权时共用栈
- 任务在运行过程中动态转换线程/协程状态

### 5.4 时钟队列优化

**问题**：等待时间极短时 alarm 可能设置失败

**解决方案**：
- timer_queue 做成超时时间排序链表
- 使用循环 set_alarm 保证 alarm 一定被正确设置
- 单 TIM 单 Channel 上升沿触发超时

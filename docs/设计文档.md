# YYDS-OS 设计文档

## 1. 项目概述

### 1.1 项目背景

YYDS-OS 是基于 MIT xv6-riscv 教学操作系统开发的增强型小型内核。项目目标是在保持 xv6 简洁性的同时，融合现代操作系统的先进特性，包括 Android、Linux 和 HarmonyOS 的优秀设计理念。

### 1.2 设计目标

- 保持内核的简洁性和可读性
- 实现丰富的系统调用接口（144个）
- 融合多系统优秀特性
- 提供完善的测试用例

## 2. 系统架构设计

### 2.1 整体架构

```
┌─────────────────────────────────────────────────────────────────┐
│                        用户空间 (User Space)                     │
├─────────────────────────────────────────────────────────────────┤
│  用户程序 → 用户库(ulib.c) → 系统调用接口(usys.S) - 144个系统调用 │
├─────────────────────────────────────────────────────────────────┤
│                              ecall (陷入内核)                    │
├─────────────────────────────────────────────────────────────────┤
│                        内核空间 (Kernel Space)                   │
├─────────────────────────────────────────────────────────────────┤
│  ┌─────────┬─────────┬─────────┬─────────┬─────────┬─────────┐ │
│  │ 进程管理 │ 内存管理 │ 文件系统 │ 网络协议 │   IPC   │ 调度器  │ │
│  │ proc/   │   mm/   │   fs/   │ network/│ Binder  │QoS/MLFQ │ │
│  └─────────┴─────────┴─────────┴─────────┴─────────┴─────────┘ │
├─────────────────────────────────────────────────────────────────┤
│                      中断/陷阱处理 (trap.c)                      │
├─────────────────────────────────────────────────────────────────┤
│              硬件抽象层: UART | PLIC | CLINT | VirtIO | E1000    │
├─────────────────────────────────────────────────────────────────┤
│                      RISC-V 64位 硬件平台                        │
└─────────────────────────────────────────────────────────────────┘
```

### 2.2 目录结构

```
kernel/
├── asm/          # 汇编代码（entry.S, swtch.S, trampoline.S）
├── driver/       # 设备驱动（console, uart, virtio_disk）
├── filesystem/   # 文件系统核心（fs.c, file.c, bio.c, log.c）
├── fs/           # 扩展文件系统（sysfs, hmdfs）
├── include/      # 内核头文件
├── interrupt/    # 中断处理（trap.c, plic.c）
├── lib/          # 库函数（printf.c, string.c）
├── lock/         # 锁机制（spinlock, sleeplock）
├── mm/           # 内存管理（kalloc, vm, slab, vma, sharemem）
├── network/      # 网络协议栈（net.c, e1000.c, pci.c）
├── proc/         # 进程管理（proc, pipe, exec, embassy, qos, binder, cgroups, ability）
└── sys*.c        # 系统调用实现
```

## 3. 核心模块设计

### 3.1 进程调度模块

#### 3.1.1 MLFQ 多级反馈队列调度器

**设计思路：**
- 实现多级优先级队列，高优先级进程优先执行
- 动态调整进程优先级，防止饥饿
- 支持时间片轮转

**核心数据结构：**
```c
struct proc {
    int priority;           // 当前优先级
    int original_priority;  // 原始优先级
    int time_slice;         // 剩余时间片
    // ...
};
```

#### 3.1.2 Embassy 异步调度器

**设计思路：**
- 借鉴 Rust Embassy 框架的异步任务模型
- 4级优先级：CRITICAL、HIGH、NORMAL、LOW
- 支持延时等待、事件触发、优先级提升

**核心接口：**
```c
int embassy_spawn(void (*fn)(void*), void *arg, int priority);
void embassy_yield(void);
void embassy_delay_ms(int ms);
int embassy_event_wait(int event_id);
```

#### 3.1.3 QoS 服务质量调度（HarmonyOS 特性）

**设计思路：**
- 6级服务质量等级，对应不同的调度策略
- 支持截止时间感知、I/O 优先级提升
- 动态负载均衡

**QoS 等级：**
| 等级 | 名称 | 时间片 | 用途 |
|------|------|--------|------|
| 0 | USER_INTERACTIVE | 5ms | 用户交互 |
| 1 | DEADLINE_REQUEST | 8ms | 截止时间敏感 |
| 2 | USER_INITIATED | 10ms | 用户发起 |
| 3 | DEFAULT | 15ms | 默认 |
| 4 | UTILITY | 20ms | 工具类 |
| 5 | BACKGROUND | 30ms | 后台任务 |

### 3.2 内存管理模块

#### 3.2.1 Slab 分配器

**设计思路：**
- 针对小对象分配优化，减少内存碎片
- 预分配多种大小的对象缓存
- 支持统计信息查询

**缓存大小类：**
```c
static int slab_sizes[] = {32, 64, 128, 256, 512};
```

#### 3.2.2 VMA 虚拟内存区域管理

**设计思路：**
- 增强的虚拟内存区域管理
- 支持匿名映射、文件映射、共享映射
- 缺页异常处理优化

**VMA 结构：**
```c
struct vma_entry {
    uint64 start;      // 起始地址
    uint64 end;        // 结束地址
    int flags;         // VMA_READ | VMA_WRITE | VMA_EXEC | ...
    struct file *file; // 关联文件（文件映射）
    int offset;        // 文件偏移
};
```

#### 3.2.3 cgroups 资源控制（Linux 特性）

**设计思路：**
- 实现进程组资源限制
- 支持 CPU、内存、I/O、PID 四种控制器
- 层次化的 cgroup 管理

**控制器功能：**
| 控制器 | 功能 |
|--------|------|
| CPU | cpu_shares, cpu_quota |
| Memory | memory_limit, memory_usage |
| I/O | io_bps_limit, io_iops_limit |
| PIDs | pids_max, pids_current |

### 3.3 进程间通信模块

#### 3.3.1 Binder IPC（Android 特性）

**设计思路：**
- 高效的跨进程通信机制
- 服务注册与发现
- 引用计数管理
- 同步/异步事务处理

**核心接口：**
```c
int binder_register(char *name, int handle);  // 注册服务
int binder_lookup(char *name);                // 查找服务
int binder_call(int handle, void *data, int size);  // 调用服务
```

#### 3.3.2 共享内存

**设计思路：**
- 支持多进程共享同一物理内存区域
- 引用计数管理
- 支持读写权限控制

#### 3.3.3 消息队列

**设计思路：**
- FIFO 消息传递
- 支持阻塞/非阻塞模式
- 消息优先级

### 3.4 文件系统模块

#### 3.4.1 sysfs 虚拟文件系统

**设计思路：**
- 暴露内核信息为文件接口
- 支持动态注册/注销节点
- 只读/读写属性

**挂载点：** `/sys`

**节点示例：**
- `/sys/kernel/version` - 内核版本
- `/sys/kernel/hostname` - 主机名
- `/sys/kernel/uptime` - 运行时间
- `/sys/memory/total` - 总内存
- `/sys/memory/free` - 空闲内存

#### 3.4.2 HMDFS 分布式文件系统（HarmonyOS 特性）

**设计思路：**
- 设备发现与管理
- 跨设备文件共享
- 文件同步与冲突处理
- 缓存优化

**核心功能：**
| 功能 | 说明 |
|------|------|
| 设备注册 | 支持手机、平板、PC、手表、电视等设备类型 |
| 文件共享 | 跨设备文件访问 |
| 同步策略 | 自动同步、手动同步 |
| 冲突处理 | 最新优先、最大优先、手动合并 |

### 3.5 应用框架模块

#### 3.5.1 Ability 框架（HarmonyOS 特性）

**设计思路：**
- 应用能力抽象
- 生命周期管理
- 页面栈导航

**Ability 类型：**
| 类型 | 说明 |
|------|------|
| Page (FA) | 前台界面能力 |
| Service (PA) | 后台服务能力 |
| Data (PA) | 数据访问能力 |

**生命周期状态：**
```
INITIAL → INACTIVE → ACTIVE → BACKGROUND → DESTROYED
```

## 4. 创新点与亮点

### 4.1 多系统特性融合

YYDS-OS 创新性地融合了三大主流操作系统的优秀特性：

| 来源 | 特性 | 创新点 |
|------|------|--------|
| Android | Binder IPC | 轻量级实现，适配教学内核 |
| Linux | cgroups | 简化版资源控制，易于理解 |
| HarmonyOS | Ability框架 | 应用能力抽象，组件化设计 |
| HarmonyOS | HMDFS | 分布式文件系统概念验证 |
| HarmonyOS | QoS调度 | 服务质量感知调度 |

### 4.2 Embassy 异步调度器

借鉴 Rust Embassy 框架设计，实现了内核级异步任务调度：
- 协作式多任务
- 优先级提升防饥饿
- 事件驱动模型

### 4.3 Slab 分配器优化

针对内核小对象分配场景优化：
- 减少内存碎片
- 提高分配效率
- 支持统计监控

### 4.4 系统调用丰富度

从 xv6 原有的 21 个系统调用扩展到 144 个，涵盖：
- 进程管理与调度
- 内存管理
- 文件系统
- 网络通信
- 进程间通信
- 用户管理

## 6. 编译与运行

### 6.1 环境要求

- Ubuntu 20.04+
- RISC-V GNU 工具链
- QEMU 5.1.0+

### 6.2 编译运行

```bash
# 编译并运行
make qemu

# 清理
make clean

# 调试模式
make qemu-gdb
```

### 6.3 测试命令

```bash
# 在 YYDS-OS shell 中运行测试
$ osfeatures_test   # 测试 Binder/cgroups/Ability
$ qostest           # 测试 QoS 调度
$ hmdfstest         # 测试 HMDFS
$ embassy_test      # 测试 Embassy 调度器
```
